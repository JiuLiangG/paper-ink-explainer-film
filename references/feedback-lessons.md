# 用户反馈铁律（原话 → 规则）

这些都来自 JL G 在《精神分析的本质》及同期《学习观》、易心八法片上的真实反馈。开工前读一遍。

| 用户原话（大意） | 规则 |
|---|---|
| 「是想要打发乞丐吗？…请你好好构思、制作和打磨，不要省token，不要摸鱼」（约 10 分钟赶出的两版被弃并删除） | 不赶工。先规划（PLAN.md）→ 静帧 → 全片 → 自查。质量优先于速度 |
| 「不要一点点改，将刚才说到的一并改了」「不要着急改完，要仔细斟酌后再进行修改」 | 收齐本轮全部意见，写一份锁定计划，一次渲染 |
| 「你改完先自查一遍」 | 交付前必须过 qa-checklist，写 SELFCHECK.md |
| 「全程使用最高强度」 | 用最强推理认真做，不偷懒；不在回复里炫耀模型 |
| 「冰山应该包括意识、前意识和无意识」「潜意识译为无意识」 | 专业准确性第一，对照权威教材，术语统一 |
| 「"是你看见的"…太绝对了」 | 用问句，不下判语 |
| 「『你注意到了吗？』后面貌似有出现一次…重复？」 | 关键句只出现一次，全工程搜 |
| 「时钟往右上角挪一挪」 | 画面元素别压字幕/气泡；角落放道具 |
| 「视频缺了点呼吸感」 | 概念块之间 ~1s 画面停顿 |
| 「各部分衔接要有一个承上启下的过渡」→ 加了桥接句后：「衔接着急的地方…更诡异了…抑扬顿挫和停顿都莫名其妙」 | 过渡＝画面呼吸＋已有承接句，**不加孤立的桥接短句** |
| 「有些莫名其妙的抖动部分，能不能做成不抖？」 | 线条默认静止，抖动只给 1–2 个关键时刻 |
| 「ending…只需要渐入显示一个红门，然后在缓缓打开的过程中zoom到全黑就行」 | 结尾极简：一个物、一个动作、无旁白、不回放 |
| 「开放式的ending」 | 不说教，把问题交还观众 |
| 「迭代地…地应该念de」「拾…改为捡」 | 每句过耳；用常用字 |
| 「我想保留现有的文件别动…v2版来改」 | 版本目录只增不改；v1 是冻结存档 |
| 「传到网盘就行」 | 交付走 Drive 链接（分享版 <100MB） |
| 「目前我还不认为这属于成片」 | 用户没认可前不做归档/打包类收尾动作 |
| 「我很喜欢你制作的完整版《精神分析的本质》」 | 这部片子就是风格基准；新片和它并排比 |
